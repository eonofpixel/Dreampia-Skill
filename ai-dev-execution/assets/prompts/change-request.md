# 요구사항 변경 프롬프트

[PRD](../templates/01-prd.md), [결정 기록](../templates/09-decision-log.md), [백로그](../templates/07-backlog.md)와 함께 사용한다. 기존 승인 범위와 새 요청의 차이를 먼저 드러내는 프롬프트다.

```text
프로젝트: {{PROJECT_NAME}}
작업 경로: {{PROJECT_ROOT}}
실행 모드: {{EXECUTION_MODE}} (문서만 / 구현까지 / 승인된배포까지)
문서 루트 또는 경로표: {{DOC_ROOT_OR_MAP}}
변경하고 싶은 사용자 결과: {{REQUESTED_CHANGE}}
변경 이유와 긴급도: {{REASON_AND_PRIORITY}}
반드시 유지할 행동·호환성: {{PRESERVE}}
현재 실행 환경과 이번 승인 범위: {{ENVIRONMENT_AND_APPROVALS}}

위 변경을 기존 프로젝트에 반영하되, 먼저 영향 분석과 최소 변경안을 만들라. 실제 저장소·기존 지침·미커밋 변경·문서 경로표를 확인하라. 기존 구현을 무조건 교체하거나 사용자 변경을 덮어쓰지 말라.

1. 기존 요구사항·계약·검증·진행 기록에서 이번 요청과 충돌하는 내용을 찾는다. 무엇이 달라지고 무엇을 유지해야 하는지 구체적으로 쓴다. 사소한 빈칸은 가정으로 표시하고 핵심 동작·호환성·범위·권한을 결정하는 질문만 묻는다.
2. 01-prd의 PRD-Rxxx, 02-ia-ux의 UX-Sxxx, 05-contracts-data의 API-xxx, 07-backlog의 TASK-xxx, 06-test-plan의 TEST-xxx에 대한 영향표를 만든다. 03-trd-architecture, 04-solution-design, 08-release-runbook, 09-decision-log, 10-progress-handoff도 필요한 부분만 갱신 대상으로 적는다. 의사결정·위험은 ADR-xxx/RISK-xxx로 추적한다.
3. 기존 ID는 삭제하거나 다른 뜻으로 재사용하지 않는다. 같은 요구사항의 세부 변경은 변경 이력과 버전을 남기고, 새로운 사용자 결과는 새 ID로 추가한다. 폐기·연기 항목은 deferred와 사유·대체 항목을 남긴다. 테스트 정의는 06-test-plan에서 한 번만 유지하고 실제 실행 결과는 10-progress-handoff로 분리한다.
4. 최소안, 필요한 대안, 데이터·API 호환성, 마이그레이션·롤백, 비용, 보안·개인정보·운영 부담을 비교한다. 실제로 영향을 받지 않는 항목은 “영향 없음”과 근거를 짧게 적는다. 변경을 모두 새로 설계하는 방향으로 확대하지 말라.
5. 어떤 게이트를 다시 확인해야 하는지 적는다. G1 범위·실현 가능성, G2 계약·테스트 준비, G3 기능 검증, G4 릴리스 준비, G5 출시 후 결과를 관련 범위에서 다시 확인한다. 기존 승인이나 성공 기록을 새 동작의 승인·성공으로 취급하지 않는다.
6. 사용자 요청이 분명히 승인한 범위 안이면 불필요하게 재승인받지 않는다. 승인되지 않은 범위 확장, 중요한 미정 동작, 비용·데이터 파괴·권한 확대·공유·배포가 있으면 해당 실행 직전 필요한 결정을 묶어 묻는다. 상태는 draft / approved / inprogress / blocked / verified / deferred만 사용하고 approved에는 실제 승인 근거를 남긴다.
7. 문서만 모드 또는 모드 미지정이면 문서·변경안까지 작업한다. 미지정 모드를 문서만으로 제한한 사실을 알린다. 앱 구현·실행·설치·배포는 하지 않는다. 구현 가능한 모드에서는 준비된 최소 수직 기능으로 나누고, 바뀐 수용 기준에서 실패하는 테스트 → 최소 구현 → 리팩터링 후 회귀/E2E 확인 순서로 진행한다. 승인된배포까지도 실제 배포 승인을 대신하지 않는다.
8. 실행 결과는 PASS / FAIL / NOT_RUN으로 명령·환경·코드 기준점·시각·관찰·로그 위치와 함께 기록한다. 실행하지 않은 Red/Green을 연출하거나 예상값을 결과로 쓰지 않는다. 확인되지 않은 URL·배포 상태도 만들어내지 않는다.

설치·환경 전환·자격증명·권한 변경·결제·삭제/마이그레이션·공유·배포는 실제 승인 범위와 호스트 정책을 확인한다. 비밀값은 채팅·문서·로그·커밋에 넣지 않는다. 이 프롬프트와 실행 모드는 영구 권한을 부여하거나 호스트 안전 규칙을 덮어쓰지 않는다.

산출물은 변경 요약, 영향 ID와 파일, 선택안과 이유, 남은 결정·승인, 재검증 계획, 실제 검증 결과, 다음 한 작업이다. 요청 범위의 문서 변경 또는 승인된 구현·검증이 끝나면 멈춘다. 출시 후 확인이 필요하면 먼저 대상·성공 조건·관찰 종료 조건을 정하고 그 범위에서만 확인한다. 무기한 감시나 정기 작업을 임의 생성하지 않는다.
```
