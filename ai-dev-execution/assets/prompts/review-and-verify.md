# 변경 검토와 검증 프롬프트

[체크리스트](../../references/checklist.md)와 [테스트 계획](../templates/06-test-plan.md)을 함께 사용한다. 기본값은 검토와 검증이다. 코드 수정은 아래 수정 허용 범위에 명시된 경우만 진행한다.

```text
프로젝트: {{PROJECT_NAME}}
작업 경로: {{PROJECT_ROOT}}
실행 모드: {{EXECUTION_MODE}} (문서만 / 구현까지 / 승인된배포까지)
문서 루트 또는 경로표: {{DOC_ROOT_OR_MAP}}
검토 대상과 코드 기준점: {{REVIEW_TARGET}}
수정 허용 범위: {{FIX_SCOPE}} (미지정이면 검토만)
실행 환경과 이번 승인 범위: {{ENVIRONMENT_AND_APPROVALS}}

위 변경이 실제 요구사항을 충족하는지 검토하라. 먼저 저장소, 기존 지침, 변경 diff, 사용자 미커밋 변경, 문서 경로표, 실행 가능한 검증 도구를 확인하라. 의도한 변경과 기존 상태를 구별하고 사용자 변경을 덮어쓰지 말라.

1. 요구사항 01-prd, UX 02-ia-ux, 아키텍처 03-trd-architecture, 설계 04-solution-design, API·데이터 05-contracts-data, 기대 검증 06-test-plan, 작업 07-backlog, 릴리스 08-release-runbook, 결정 09-decision-log, 실제 실행 기록 10-progress-handoff를 비교한다. PRD-Rxxx → UX-Sxxx/API-xxx → TASK-xxx → TEST-xxx 연결의 누락·불일치를 찾는다.
2. 가장 중요한 사용자 흐름부터 확인한다. 화면만 보지 말고 입력 → API → 인가 → 저장 → 재조회 → 화면 결과를 연결한다. 관련된 오류·빈 상태·로딩·재시도·동시성·시간대·접근성·보안 경계를 확인한다. 실제 외부 서비스 대신 더블을 썼다면 확인되지 않은 경계를 밝힌다.
3. Red가 의도한 이유로 실패했는지, Green이 수용 기준을 만족하는지, Refactor 후 같은 행동이 유지되는지 확인한다. 누락된 과거 Red를 재현한 것처럼 쓰지 않는다. 필요하면 현재의 결함을 재현하는 회귀 테스트를 제안한다.
4. 문서만 모드에서는 문서와 정적 증거만 검토한다. 앱 구현·실행·설치·배포는 하지 않는다. 다른 모드에서는 허용된 테스트 환경에서 기존 명령을 실행할 수 있지만, 비용·외부 데이터 변경·실서비스 부하를 일으키는 검증은 별도 승인 범위를 확인한다. 모드가 비어 있으면 문서만으로 제한한 사실을 알린다.
5. 테스트마다 PASS / FAIL / NOT_RUN과 명령·환경·코드 기준점·시각·관찰·로그 위치를 남긴다. 테스트 계획은 기대 결과이고 인수인계는 실제 결과다. 출력이 없거나 실행하지 못했다면 성공으로 추론하지 않는다. 확인하지 않은 링크·배포 URL·성능 수치를 만들지 않는다.
6. 문제는 사용자 영향, 재현 조건, 근거 파일·위치, 관련 ID, 권장 수정, 출시 차단 여부 순으로 쓴다. 중요도가 높은 문제부터 제시하되 추측은 추측으로 표시한다. 핵심 의사결정이나 권한이 없을 때만 질문하고 나머지 독립 검증은 계속한다.
7. 수정 허용 범위가 있으면 그 안의 결함만 고친다. 실패를 보여 주는 테스트 → 최소 수정 → 관련 회귀 테스트 순서로 진행한다. 허용되지 않은 코드·설정·계약 변경은 제안으로 남긴다. 계약 변경이 필요하면 change-request 절차로 돌린다.
8. 상태는 draft / approved / inprogress / blocked / verified / deferred를 사용한다. 필수 검증이 FAIL 또는 NOT_RUN이면 G3를 통과 처리하지 않는다. G4는 배포 권한, 설정, 마이그레이션·롤백, 관측·운영 책임까지 충족해야 한다. G5는 실제 배포가 있고 정의된 출시 후 결과를 확인했을 때만 판단한다.

환경 전환, 설치, 자격증명·보안 권한, 비용·결제, 삭제·마이그레이션, 공유, 배포는 실제 승인과 호스트 정책을 확인하라. 비밀값을 채팅·문서·로그·커밋에 쓰지 말라. 프롬프트·문서·실행 모드는 영구 권한을 만들거나 호스트 안전 규칙을 대체하지 않는다.

보고 형식:
- 결론: 확인된 결과와 확인되지 않은 부분
- 출시를 막는 문제, 그 밖의 개선 사항
- PRD/TEST ID별 실제 PASS/FAIL/NOT_RUN과 근거 위치
- 현재 게이트, 남은 결정·승인, 권장 다음 단계
- 갱신한 실제 문서 경로

검토 범위의 검증이 끝나거나 필요한 입력·권한에 막히면 기록하고 멈춘다. 요청하지 않은 배포·공유·예약 작업·무기한 감시를 시작하지 않는다.
```
