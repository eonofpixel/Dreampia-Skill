# AI 개발 작업 규칙 템플릿

이 파일은 재사용 원본이다. 현재 폴더의 자동 실행 지침이 아니다. 실제 프로젝트의 기존 지침과 사용하는 AI의 형식을 확인한 뒤 필요한 내용을 승인된 경로에 병합한다. 이 문서는 시스템·안전 정책이나 도구의 승인 요구를 바꾸지 않고 지속적인 외부 행동 권한을 부여하지 않는다.

- 프로젝트 이름: {{PROJECT_NAME}}
- 프로젝트 루트: {{PROJECT_ROOT}}
- 실행 모드: {{EXECUTION_MODE}} = 문서만 / 구현까지 / 승인된배포까지
- 진행 범위: {{PROGRESS_SCOPE}} = 단일기능 / 승인된마일스톤
- 목표 기능·마일스톤과 완료 조건: {{TARGET_MILESTONE_ID}} / {{TASK_IDS}} / {{DEFINITION_OF_DONE}}
- 기준 문서 지도: {{PROJECT_DOCUMENT_MAP_PATH}}
- 현재 진행·인계: {{HANDOFF_PATH}}
- 허용 수정 경로·금지 범위: {{ALLOWED_PATHS}} / {{FORBIDDEN_ACTIONS}}
- 결정권자·비용 상한·외부 변경 승인: {{OWNER}} / {{BUDGET}} / {{APPROVAL_REFERENCES}}

## 시작

1. 브리프, 문서 지도, 진행·인계, 현재 작업의 요구·계약·테스트를 읽는다.
2. 저장소·지침·기존 변경·브랜치·환경·실제 명령을 확인한다. 신규 프로젝트라고 기존 파일을 지우거나 초기화하지 않는다.
3. 확정 사실·가정·미확인·승인 대기를 분리한다. 중요한 제품·권한·비가역 결정만 질문하며 추천안과 영향을 같이 제시한다.
4. 범위 안의 되돌릴 수 있는 기술 선택은 이유를 적고 진행한다. 접근이나 승인이 없으면 그 부분을 막고 독립 작업을 계속한다.

## 구현과 검증

- 요구·UX·계약·작업·테스트 ID를 연결한다. 정확한 값은 기준 문서 한 곳에 두고 참조한다.
- 사용자 가치가 끝까지 이어지는 작은 기능 조각으로 작업한다. 파일 소유권·DAG·공통 계약을 확인한 독립 작업만 병렬화한다.
- 핵심 결정적 로직은 Red → Green → Refactor로 진행한다. 의도한 실패를 실제로 확인하고 관련 회귀 검사를 다시 실행한다.
- 통과시키기 위해 테스트를 삭제·완화하거나 결과를 조작하지 않는다. 명세 오류는 근거와 영향 분석을 거쳐 바꾼다.
- 실제 테스트 백엔드·격리 데이터로 권한·저장·경쟁 조건과 사용자 E2E를 확인한다. UI는 상태·화면 크기·접근성을 확인한다.
- AI 제품 기능은 평가 세트·rubric·홀드아웃·치명 실패·비용·지연을 별도로 검증한다.
- 검사 결과는 PASS / FAIL / NOT_RUN으로 기록한다. 실제 환경·버전·시각·명령·증거를 제시하며 없는 파일·URL·출력을 만들지 않는다.
- 문서·테스트·구현의 차이를 해소하고 제품 인수 조건을 별도 검토한다. 전체 커버리지나 무중단 실행을 보장하지 않는다.

## 권한과 연속 진행

- 문서만 모드에서는 앱 구현·설치·배포·외부 변경을 하지 않는다.
- 비밀은 안전한 공급 절차로만 사용하며 채팅·문서에 요구·복제하지 않는다.
- 비용, 설치, 인증·영구 접근, 데이터 삭제·변경, 공유·발송, 배포는 구체적인 승인 범위를 따른다. 모드 선택만으로 승인됐다고 보지 않는다.
- 단일기능이면 해당 기능 DoD까지 진행한다. 승인된마일스톤이면 검증된 기능 뒤 다음 준비 작업을 계속하며 매번 진행 여부를 묻지 않는다.
- 게이트는 근거 확인 단계다. 위임된 기술 단계마다 수동 승인을 요구하지 않는다. 제품·권한·중대한 변경의 승인은 생략하지 않는다.
- 목표 DoD 완료, 사용자의 중단, 또는 더 진행할 독립 작업이 없는 필수 입력·승인·접근·품질 차단에서 멈춘다. 범위를 스스로 확대하거나 배포하지 않는다.
- 외부 작업을 기다리면 대상·기대 결과·관찰 근거·종료 조건을 정한다. 지원되지 않는 상시 작업을 약속하거나 근거 없이 반복 재시도하지 않는다.

## 보고와 인계

매 기능 또는 의미 있는 변경마다 다음을 짧게 남긴다.

1. 완료한 결과와 요구·작업 ID
2. 실제 검증과 PASS / FAIL / NOT_RUN
3. 남은 위험·차단·필요한 결정
4. 다음 준비 작업과 계속·중단 조건

종료·컨텍스트 전환 전에는 현재 버전, 미커밋 변경, 실행 프로세스, 실패 재현, 예산·접근 한계, 승인 대기, 다음 작업을 저장한다. 다른 세션에서 환경과 버전을 재확인하기 전 과거 PASS를 현재 PASS로 복사하지 않는다.
