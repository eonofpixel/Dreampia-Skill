- 다음 판단 시점: {{기능 검증 완료 또는 실제 외부 작업의 결과 확인 조건}}

24시간 실행이나 무중단 완수를 가정하지 않는다. 실행 도구·컨텍스트·권한이 끝나기 전에 인계를 남긴다. 진행 중인 승인된 작업은 결과가 확정될 때까지 목적에 맞게 확인하되, 권한과 비용 범위를 넘기지 않는다.

`승인된마일스톤`이면 각 기능 검증 뒤 의존성이 해소된 다음 TASK를 계속하며 일상적인 진행 여부를 매번 묻지 않는다. 전체 마일스톤 DoD를 충족하거나 필수 승인·입력·접근·품질 문제가 실제로 막는 지점에서 멈춘다. 차단된 작업과 독립적인 Ready 작업은 승인 범위 안에서 계속한다. 게이트마다 새로운 수동 승인이 필요한 것은 아니며, 범위 확대나 배포 권한이 자동으로 생기지도 않는다.

## 4 시작 준비 조건: Ready

이 절은 체크리스트이며 별도 상태값이 아니다. 부족한 내용이 핵심 경로에 영향을 주면 `blocked`로 기록한다.

- [ ] 요구·인수 조건·소유자와 범위 승인이 확인됐다.
- [ ] 계약·데이터·권한·오류 의미와 불변식이 충분히 정의됐다.
- [ ] 중요한 미지수는 실험으로 검증됐거나 승인된 제외 범위로 정리됐다.
- [ ] 선행 작업의 필요한 결과가 검증됐고 계약 버전이 맞는다.
- [ ] 테스트 환경·데이터·명령·증거 보관 경로가 준비됐다.
- [ ] 소유 파일과 공유 리소스에 병렬 충돌이 없다.
- [ ] 필요한 실행 권한·비용 한도·중단 조건이 확인됐다.

## 6 완료 조건: Done

- [ ] 요구와 정상·거부·경계·복구 인수 조건을 충족했다.
- [ ] 핵심 로직은 유효한 Red → Green → Refactor 증거가 있다. 예외는 이유가 있다.
- [ ] 계약·실제 저장·권한·동시성 경로와 영향받는 회귀 검사를 확인했다.
- [ ] UI 상태·반응형·접근성 및 해당 비기능 요구를 검증했다.
- [ ] 제품 인수 검토를 테스트 통과와 별도로 기록했다.
- [ ] 문서·테스트·코드 간 변경을 정합화했다.
- [ ] 실제 증거의 버전·환경·시각·검증자와 잔여 위험을 기록했다.
- [ ] 미실행/실패 항목은 `NOT_RUN`/`FAIL`로 남기고 차단 여부를 명시했다.

완료 판정자/시각: {{이름 / 시각과 시간대}} · 증거: {{미생성}} · 상태: {{draft 등}}

필수 검증이 남아 있으면 코드 작성이 끝나도 `verified`로 바꾸지 않는다. 비차단 위험을 연기할 때는 결정권자·이유·기한/재검토 조건을 기록한다. `verified`는 해당 TASK 범위의 검증이며 운영 배포 승인이 아니다.
