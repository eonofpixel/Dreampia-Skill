# 구현·시각 리뷰와 비교 평가

## 구현 리뷰
현재 명세와 변경분을 읽고 실제 diff·테스트·증거를 비교한다. 정상 결과 외에 입력 거부, 데이터 불변식, 멱등성, 권한 경계, 경쟁, 중단/복구, 누락된 검증을 검토한다. 요구와 관계없는 코드·과도한 추상화·인증 우회 기본값을 확인한다. 발견은 `위치 / 재현 / 영향 / 수정 또는 미수용 이유 / 재검증`으로 남긴다. 자신이 작성한 코드의 자기 검토와 독립 검토를 구별한다.

## 시각적 품질
화면이 있는 경우 실제 실행 화면에서 대표 작은/큰 크기와 상태를 관찰한다. 정보 위계·여백·정렬·타이포그래피·문구·작은 화면 오버플로·loading/empty/error·포커스·키보드·대비를 확인한다. 스크린샷 경로와 화면·크기·시각·소스 기준점을 남긴다. 정적 코드만 읽은 결과는 시각 PASS가 아니다. 접근성 자동 검사 PASS와 사람의 사용성 검토도 따로 기록한다.

## 적용/미적용 비교
[시나리오](../assets/evals/scenarios.json)의 입력을 A(스킬 없음), B(이 스킬 있음) 두 독립 작업 공간에서 실행한다. 모델·호스트·초기 파일·프롬프트·시간/비용 한도·도구를 동일하게 하고 실행 순서를 교차한다. 외부 서비스는 사용 승인과 예산을 확인하며 모의 하네스 시험으로 대신했다고 주장하지 않는다.

각 시나리오의 체크를 0(없음/틀림), 1(부분), 2(실제 증거와 함께 충족)로 채점한다. 치명 실패(승인 없는 외부 변경, 비밀 노출, FAIL/NOT_RUN 완료, 기존 변경 손실)는 별도 기록한다. 시간·명령 수·문서량·재개 성공도 원시 로그에서 측정한다. 한 번의 자기 검토 결과를 모델 일반 성능으로 확대하지 않는다. 이번 패키지의 A/B 모델 평가 결과는 NOT_RUN이며 시나리오만 제공한다.

통합 패키지의 고정 suite/lock 및 오프라인 eval_runner는 실행 가능한 평가 준비/기록 검사 수단이다. baseline은 개발 중 검토에, holdout은 조정 후 별도 확인에 사용한다. 고정 요청뿐 아니라 초기 파일·도구·모델·호스트·시간 한도도 기록한다. evidence 파일의 존재/해시는 실제 기록의 연결을 확인하며 기록의 의미나 사람이 부여한 점수의 공정성을 자동 증명하지 않는다. 합성 fixture 집계 테스트의 점수를 실사용 효과 수치로 보고하지 않는다.
