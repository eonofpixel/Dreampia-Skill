## G2 기능 시작 준비

- [ ] 요구 → UX·계약·설계 → 작업 → 테스트가 연결된다.
- [ ] 로딩·빈 상태·오류·권한·재시도·취소·접근성을 다뤘다.
- [ ] 타입·시간대·오류·권한·멱등성·동시성·데이터 제약을 정했다.
- [ ] 실제 검증 환경·계정·격리 데이터가 준비됐다.
- [ ] 작업 DAG·담당자·소유 파일·검증·중단·재개 조건이 있다.
- [ ] 프로토타입과 운영 구현의 경계·폐기·재검증 조건이 있다.

## G3 기능 완료

- [ ] 핵심 결정적 로직의 Red 실패 이유를 실제 실행으로 확인했다.
- [ ] 최소 Green 구현과 Refactor 뒤 관련 회귀 검사를 실행했다.
- [ ] 테스트를 약화하거나 실패를 숨기지 않았다.
- [ ] 실제 테스트 백엔드에서 저장·권한·경쟁 조건을 검증했다.
- [ ] 브라우저·기기에서 핵심 E2E와 화면·접근성을 확인했다.
- [ ] 구현 테스트와 별도로 PRD 인수 조건을 검토했다.
- [ ] 해당 보안·성능·복구·개인정보·비용 영향을 검사했다.
- [ ] AI 기능이 있으면 버전 고정 평가·홀드아웃·치명 실패 기준을 확인했다.
- [ ] 실행 명령·환경·버전·시각·결과·증거가 있고 NOT_RUN을 숨기지 않았다.
- [ ] 문서·코드·테스트의 변경을 맞추고 백로그·인계를 갱신했다.
