# 모바일·태블릿 앱 선택 참조

iOS/Android 및 해당 앱 스택의 실제 화면이 범위일 때 읽는다. 모바일 웹은 design-web이 기본이며 웹/PWA·webview·native의 차이를 먼저 구별한다. iOS 스타일을 Android에 그대로 이식하거나 웹 CSS/ARIA를 native 계약으로 쓰지 않는다.

## 화면·플랫폼과 입력

- 대상 OS·지원 폰/태블릿·방향·실제 스택/SDK를 확인한다. 기존 시스템 컴포넌트·테마·내비게이션을 우선한다. 라이브러리 이름이나 최신 SDK 예제를 현재 앱에 무조건 도입하지 않는다.
- iOS의 뒤로가기/시트·Android back와 navigation·platform accessibility 역할/상태를 각각 지킨다. 중요한 gesture-only 동작에는 보이는 조작/접근성 대체 경로를 둔다. 탭/스크롤/시스템 제스처가 충돌하지 않게 한다.
- hit 영역과 보이는 아이콘을 구별한다. 터치 지향 화면의 기준 예는 iOS44×44pt, Android48×48dp다. 플랫폼별 단위/간격·실제 설정을 확인하며 desktop pointer나 웹 target에 같은 숫자를 강제하지 않는다.
- safe area·시스템 bar·키보드가 입력/주요 행동을 가리지 않게 한다. 키보드가 열린 상태에서 입력→오류 수정→저장/취소를 확인한다. 한글 조합·긴 이름·큰 글자 설정에서 잘림/겹침을 확인한다.
- 지원한 작은/큰 창과 태블릿 분할 화면에서 구조를 다시 배치한다. 폰 화면을 단순 확대하지 않는다. 지원하지 않는 폴더블/방향/태블릿은 미적용 이유만 남기고 모든 조합을 의무화하지 않는다.

## 데이터·상태와 접근성

첫 로딩을 빈 결과로 표시하지 않는다. 재조회·refresh·오프라인·실패가 요구되면 기존 내용과 미확정 상태를 구별하고 입력/진행을 보존한다. 백그라운드 전환·복귀·화면 재진입 시 선택/작업/요청 중복이 어떻게 처리되는지 실제 계약과 맞춘다. 임의 persistence나 권한·계정 기능을 범위에 추가하지 않는다.

제출/검색이 있는 흐름은 한글 조합 중 검증·제출, 화면을 떠났다가 돌아온 뒤 늦은 응답·취소/재시도와 중복 제출을 필요한 작업 계약으로 정한다. 서버 수락 여부가 미확정이면 성공/실패를 임의 확정하지 않는다.

VoiceOver/TalkBack에서 이름·역할·상태·순서·변경 알림을 확인한다. native 표준컨트롤도 사용자 label과 연결된 상태가 맞는지 검증한다. 시스템 글자 확대, 대비/테마, 감소 모션을 지원범위에서 확인한다. haptic은 필요하고 허용된 플랫폼에서만 보조 피드백으로 쓰고 유일한 성공/오류 신호로 삼지 않는다.

## 실제 검증

대상 simulator/emulator의 앱 UI에서 터치·키보드·뒤로가기·선택한 상태와 실제 기능 연결을 확인한다. 웹 미리보기는 native 터치·safe area·접근성·OS lifecycle 증거를 대신하지 않는다. 실기기가 필요한 제스처/하드웨어/성능은 기기 관찰을 별도 기록한다. emulator 검증 범위와 실기기 NOT_RUN을 분리하고 하드웨어 기능 완료를 주장하지 않는다. 테스트 계정/기기를 새로 등록하거나 외부 빌드/스토어 배포를 자동 실행하지 않는다.
