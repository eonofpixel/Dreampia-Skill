# 게이트별 통과와 실패 처리

[워크플로](workflow.md)와 함께 사용한다. 단계별 확인용 원본은 [체크리스트](checklist.md)다.

게이트는 문서를 많이 썼는지를 보는 절차가 아니다. 다음 위험을 감당할 준비와 증거가 있는지 확인하는 지점이다. 게이트 소유자는 프로젝트 브리프에 정한다. 승인 대기, 환경 대기, 품질 실패를 구분해 기록한다.

## G0 시작 조건 확인

- 입력: 아이디어, 사용자 요청, 환경·저장소 현황.
- 출력: 브리프, 실행 모드·규모·문서 지도, 권한 범위, 미지수 목록.
- 진입: 요청의 목적과 작업 대상이 식별된다.
- 종료: 선택한 환경·기존 변경·데이터 존재 여부를 확인했거나 미확인 범위가 명시됐다. 탐색 권한이 있고 무단 변경 위험이 없다.
- 반드시 멈춤: 작업 대상 충돌, 필요한 읽기 접근 거부, 비밀 공유 요구, 승인되지 않은 초기화·삭제.
- 계속 가능: 허용된 자료 기반 문제 정리와 문서 초안.
- 실패 조치: 확인할 대상과 최소 권한을 질문하고 의존 작업을 `blocked`로 둔다.

## G1 범위와 실현 가능성

- 입력: 브리프, PRD 초안, 의존성·실험 결과.
- 출력: 첫 릴리스 범위, 측정 가능한 인수 조건, 주요 위험 대응, 중요한 ADR.
- 진입: 해결할 사용자 문제와 제약이 정리돼 있다.
- 종료: Must와 제외선이 정해졌고 위험한 가정에 근거가 있다. 핵심 제품 결정과 비용 한도가 승인됐다.
- 반드시 멈춤: 불가능하거나 검증되지 않은 핵심 연동, 규정·권한 문제, 합의되지 않은 제품 범위.
- 계속 가능: 독립적인 UX 탐색, 대안 조사, 비용 없는 제한된 실험 설계.
- 실패 조치: 범위 축소·대체안·추가 실험을 제안하고 검증되지 않은 구현 약속을 철회한다.

## G2 계약과 테스트 준비

- 입력: PRD, UX, 기술·상세 설계, 계약, 테스트 계획, 첫 기능 백로그.
- 출력: 시작 준비 조건을 만족한 기능 조각, 안정적인 계약, 재현 가능한 검증 방법.
- 진입: G1 범위와 주요 제약이 유효하다.
- 종료: 인수 조건→계약→작업→테스트 연결, 권한·오류·데이터 불변식, 실제 검증 환경이 준비됐다.
- 반드시 멈춤: 보안·데이터 무결성에 중요한 미정 계약이나 충돌 파일 소유권에 의존하는 실행. 검증 도구가 없는 핵심 경로는 검증·완료 판정을 차단한다.
- 계속 가능: 영향 없는 문서 보완, 격리된 UI 모형, 다른 준비된 기능 조각. 화면/조작 검증 도구만 부족하다면 안전하게 구현·빌드·단위/엔진 검증 가능한 부분은 진행하고 미실행 항목은 NOT_RUN으로 남긴다. 이를 G2 전체 충족이나 기능 전체 완료로 쓰지 않는다.
- 실패 조치: 계약을 합의하거나 실험으로 확인하고, 미준비 작업을 분리한다. 모형은 프로토타입으로 표시한다.

## G3 기능 검증

- 입력: 구현·테스트, 해당 명세, 실제 실행 결과.
- 출력: 인수 조건별 판정, 회귀·UI·통합 증거, 갱신된 문서와 위험.
- 진입: G2가 충족됐고 변경 범위가 알려져 있다.
- 종료: 해당 기능의 합의된 검증이 통과했고 중요한 인수 조건이 실제 사용자 흐름으로 확인됐다. 미검증 사항이 숨겨져 있지 않다.
- 반드시 멈춤: 핵심 테스트 실패, 권한 우회·데이터 손상, 조작된 증거, 실제 백엔드가 필수인 핵심 흐름의 미검증.
- 계속 가능: 독립 기능, 실패 원인 분석, 승인 범위 내 수정·재검증.
- 실패 조치: 재현 테스트와 결함 작업을 만들고 수정한다. 기준 자체가 틀렸다면 변경 요청으로 돌아간다.

## G4 출시 준비

- 입력: G3 근거, 전체 회귀·비기능 결과, staging 결과, 런북·백업·복구 계획.
- 출력: 출시 준비 판정, 정확한 릴리스 대상·버전, 남은 위험 수용과 필요한 배포 승인.
- 진입: Must 기능이 검증됐고 릴리스 후보를 고정했다.
- 종료: 운영 설정·데이터 변경·관측·복구·담당자가 준비됐으며 승인된 위험 외 차단 결함이 없다.
- 반드시 멈춤: 복구할 수 없는 미승인 변경, 비밀 유출, 백업·복원 미확인 중요 데이터, 배포 권한·예산 부족.
- 계속 가능: 릴리스 노트, 복구 리허설, 배포 승인 준비, 독립적인 차기 요구 정리.
- 실패 조치: 릴리스를 보류하고 결함·권한·복구 중 빠진 근거를 보완한다. G4 통과를 실제 배포 완료로 표시하지 않는다.

## G5 운영과 성과 확인

- 입력: 실제 배포·smoke 결과, 관측 데이터, 약속한 결과 지표.
- 출력: 정상 운영 여부, 제품 목표 판정, 후속 결정과 책임자.
- 진입: 승인된 릴리스가 실제로 배포됐고 측정이 동작한다.
- 종료: 정한 관찰 조건에 따라 안정성과 성과를 평가했다. 근거 부족은 부족으로 기록하고 다음 행동을 정했다.
- 반드시 멈춤: 개인정보·보안 사고, 데이터 무결성 위반, 승인 한도 초과, 롤백 임계값 초과. 필요한 운영 조치는 별도 권한을 따른다.
- 계속 가능: 읽기 전용 진단, 사용자에게 영향·결정 요청, 승인된 복구·완화.
- 실패 조치: 런북에 따라 승인 범위 안에서 완화·복구하고 원인과 재발 방지 작업을 연결한다. 성과 실패는 다음 제품 가설로 돌린다.
