# 데스크톱 앱 선택 참조

Mac/Windows/Linux 등 실제 앱 창이 사용자 표면일 때 읽는다. SwiftUI/AppKit·Electron/Tauri 등 현재 스택과 대상 OS를 확인하고, Mac의 관례를 다른 OS에 일률 적용하지 않는다. webview 콘텐츠에는 design-web의 웹 의미/검증도 적용하되 창·메뉴·OS 상호작용은 별도로 확인한다.

## 제품 창과 상태 소유권

주 창·보조 창·설정·메뉴바/트레이 중 이번 범위를 정한다. 창 닫기와 프로세스 종료/작업 취소가 같은 뜻인지 명시한다. 여러 창을 지원하면 선택 항목·문서·진행 작업의 소유자가 어느 창/공유 모델인지 정하고, 활성 창이 바뀐 뒤 메뉴/단축키가 다른 항목에 작동하지 않도록 검증한다. 다중 창·트레이·전체화면은 요청 범위일 때만 구현한다.

## 조작과 레이아웃

- 기존 브랜드와 OS 기본 컨트롤·의미·초점·선택/비활성 상태를 보존한다. 새 UI framework나 특정 시각 효과를 디자인 변경 때문에 의무로 도입하지 않는다. OS/API 버전별 동작은 대상 SDK 공식문서/기존 프로젝트에서 확인하고 필요한 fallback을 둔다.
- 최소/대표/넓은 창에서 주요 행동·목록·상세가 유지되는지, split/sidebar/표가 줄어들 때 어떤 순서로 재배치되는지 정한다. 화면 전체 크기보다 현재 창/컨테이너 크기를 기준으로 한다.
- 키보드 순서·Escape/Return·메뉴/단축키·텍스트 편집과 충돌을 확인한다. Mac에서 Cmd 관례/VoiceOver·키보드 탐색 설정을 확인하고, 다른 OS에서는 해당 관례와 보조 기술을 확인한다.
- 한글 입력기 조합·긴 파일명·줄바꿈·복사/붙여넣기를 실제 콘텐츠로 시험한다. 사용자 데이터에 필요한 선택/복사 경로를 제공한다.
- 파일 열기/저장·drag/drop·권한 요청은 기능에 필요할 때만 다루고 허용된 테스트 데이터로 확인한다. 취소/잘못된 파일/쓰기 실패·미저장 변경·재시도 안전성은 실제 기능 계약과 연결한다. native 파일 대화상자/표준 컨트롤을 쓸 수 있으면 그 의미를 재활용한다.

실행/취소 UI는 작업 ID와 창의 연결을 유지한다. 취소 요청·엔진 종료/자식 정리 완료·자연 종료와의 경쟁을 구별하고 실제 완료 전에 성공/취소 완료로 표시하지 않는다. 이 조건은 현재 엔진의 계약/검증 증거로 확인한다.

## 실제 검증

대상 앱의 실제 창에서 조작→엔진/데이터→창 결과를 확인한다. 내부 에뮬레이터/콘솔 화면·webview만의 캡처는 외부 앱 창의 menu/focus/lifecycle 증거가 아니다. 크기·키보드·실제 선택·닫기/재열기/작업 지속 등 범위의 상태를 확인하고 VoiceOver/보조 기술을 따로 판정한다. UI 테스트 runner·접근성 트리와 실제 캡처/관찰을 보완적으로 사용한다. 앱 관찰 도구가 없으면 구현/빌드/엔진 검증은 가능 범위에서 진행하고 창 시각/조작은 NOT_RUN이다.

성능 문제를 관찰한 경우만 범위가 정해진 대상 프로파일링을 제안한다. 원치 않은 모든 앱의 추적·전역 녹화·자동 Instruments 실행은 하지 않는다. 브라우저 자동화만으로 native 앱 조작 완료를 주장하지 않는다.
