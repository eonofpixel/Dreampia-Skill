# 웹 UI 선택 참조

브라우저에서 사용하는 제품 화면일 때 읽는다. 네이티브 앱의 화면 구조·API에 HTML/CSS 규칙을 강제하지 않는다. 플랫폼 공통 책임은 product-design에 둔다.

## 구현 전 맞출 범위

지원 브라우저·실제 경로·좁은/넓은 사용 폭과 필수 흐름을 정한다. 기기 이름만으로 레이아웃을 고정하지 말고 콘텐츠와 기존 breakpoint에서 무엇이 재배치되는지 정한다. 필터/탭/페이지 등 새로고침·뒤로가기·공유로 유지해야 하는 상태만 URL/저장과 연결한다. 비밀이나 임시 입력까지 URL에 복사하지 않는다.

## 화면과 입력

- 기존 컴포넌트·CSS 변수/토큰을 쓰고 콘텐츠가 늘 때의 줄바꿈·표/목록 스크롤·좁은 레이아웃을 정한다. 한국어 제목·긴 이름·숫자·빈 데이터·실제 긴 목록으로 확인한다. 잘림은 상세 확인 경로를 남긴다.
- 버튼은 행동, 링크는 이동의 의미를 유지한다. 아이콘 단독 조작에 이름을 주고 폼의 실제 레이블·입력 유형·오류 연결을 제공한다. 표준 요소를 우선하고 ARIA로 잘못된 의미를 덮지 않는다.
- 키보드만으로 핵심 흐름이 가능하고 초점이 보이며 sticky 헤더·모달에 가려지지 않도록 한다. 대화상자 닫기와 초점 복귀, 비동기 상태/오류의 스크린리더 전달을 실제 확인한다. 업데이트마다 초점을 강제로 이동하거나 과도하게 읽지 않게 한다.
- hover는 보조 피드백이다. 터치·키보드로 핵심 기능이 가능하게 한다. drag/swipe에 필요한 대체 조작을 제공한다. 확대를 막지 않고 지원한 확대/글자 크기에서 흐름을 확인한다.
- 이미지/폰트 로딩으로 핵심 조작이 이동하거나 글자가 사라지지 않게 한다. 목록 가상화나 lazy loading은 실제 데이터/측정 병목에 맞춰 선택하고 고정 항목수로 의무화하지 않는다. 모션은 의미와 중단/감소 동작을 확인한다.

한국어 검색/편집이면 IME 조합 중 검색·검증·Enter 처리를 정한다. 연속 검색의 이전 응답이 최신 결과를 덮지 않는지, 항목 변경/취소 후 늦은 저장 응답과 미저장 입력이 어떻게 처리되는지 필요한 실제 계약과 맞춘다.

## 실제 검증

지원 폭·브라우저와 상태를 묶어 렌더링/캡처하고 핵심 클릭·키보드·새로고침/뒤로가기를 수행한다. 접근성 자동 검사는 후보 발견이며 실제 스크린리더/키보드·시각 품질을 대체하지 않는다. DOM/빌드만 확인했다면 렌더/조작 검증은 NOT_RUN이다.

웹 대비와 터치 기준은 적용 WCAG 수준·예외를 명시한다. 예를 들어 WCAG2.2 AA 일반 텍스트4.5:1/큰 텍스트3:1, pointer target24×24 CSS px는 각각 예외를 포함한 기준이다. 터치 편의를 위해 더 크게 설계할 수 있으나 44pt(iOS)·48dp(Android)와 같은 단위/의무로 혼용하지 않는다. 일부 항목 통과를 전체 WCAG 인증이라 부르지 않는다.
