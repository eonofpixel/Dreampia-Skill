# 독립 사례 검토 (실제 제품 실행 아님)

최소 task-local 맥락과 현재 스킬을 전달한 독립 agent가 UI 요청/CLI-only 요청을 read-only 실행 계획으로 평가했다. 실제 구현·앱 조작·시각 검증·효과 A/B는 NOT_RUN이다.

A: 기존 브랜드의 에뮬레이터 목록/선택/실행/중단 데스크톱 앱, 엔진 실행/입력 PoC 존재, 앱 조작 도구 없음. 결과: 제품 창·브랜드·목록/중단 계약을 먼저 확인하고 엔진 PoC가 제공하지 않은 기능을 가정하지 않는다. 실제 앱 구현·빌드·엔진 검증은 가능한 범위에서 진행한다. 제품 창에서 실행/중단 결과·상태·창 크기·키보드 등 필요한 인수를 확인해야 완료다. 앱 검증 도구 부재는 NOT_RUN과 전체 완료 차단이며 Android 내부 화면/CLI 결과는 호스트 UI 증거가 아니다.

B: GUI 없는 CSV 정리 CLI, 출력 파일 저장·잘못된 입력 오류. 결과: 미정 정리 규칙을 확인하고 입출력·오류·덮어쓰기 정책을 정의한다. 명령 실행→출력 파일 재조회·오류/보존 행동을 검증한다. UI/시각 검토는 미적용이며 GUI나 디자인 문서/API 의존성이 필요 없다.

실질 P2: 기존 quality-gates G2가 검증 도구 부재 때 구현까지 중단하게 해석될 수 있어 새 디자인 절차와 충돌. 수정: 미정 보안/데이터 계약·소유권 충돌에 의존한 실행은 중단하되, 도구 부재는 검증/완료 판정만 차단하고 안전한 구현·빌드·단위/엔진 검증은 계속 허용. NOT_RUN 유지.

보완: workflow 소형3~4개 표에 간편 한 파일 우선 예외를 추가. 기존 핵심 SKILL 축약에서 중요한 권한/TDD/재개/증거 무효화/하네스 보장 한계 누락은 발견되지 않았다.

두 번째 독립 검토는 수정한 두 절만 읽었다. 이전 P2 충돌과 문서 과잉 유도 여지가 해소됐으며 해당 범위에 남은 결함 없다고 보고했다. 이는 실행 계획 검토이며 실제 제품 검증 PASS를 의미하지 않는다.
